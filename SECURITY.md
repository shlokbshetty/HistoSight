## 2. Security Architecture & Operational Considerations

- **Uploaded Image Sanitization & Ephemeral Storage (`backend/main.py`)**:
  - Endpoints accepting file uploads (`POST /predict`, `POST /gradcam`, `POST /explain`) strictly validate file extensions against an explicit allowlist (`{".jpg", ".jpeg", ".png", ".bmp", ".tiff", ".tif"}`) before writing to a randomized `tempfile.NamedTemporaryFile(delete=False)`.
  - Every upload endpoint wraps execution in a `try...finally` block that guarantees `os.unlink(tmp_path)` is called immediately after inference completes, ensuring zero patient/specimen data persists on disk.
- **Server-Side Path Handling (`POST /batch_predict` & `GET /graphs/{filename}`)**:
  - `POST /batch_predict` reads local server directories specified by the operator. When deploying HistoSight in multi-tenant clinical environments, restrict `/batch_predict` and `/train_baseline` behind an authenticated API gateway and configure `CORSMiddleware` `allow_origins` to your trusted domain.
- **Model Checkpoint Integrity (`checkpoints/*.pth`, `models/*.pth`)**:
  - Only load `.pth` checkpoints generated by trusted training runs (`train.py`, `fine_tune.py`). Never load untrusted third-party pickle/checkpoint files.

## 3. Vulnerability Disclosure Process

If you discover a security issue (e.g., path traversal in `/graphs/{filename}` or `/batch_predict`, denial-of-service via malformed TIFF/HDF5 payloads, or unsafe deserialization):

1. **Do NOT disclose the issue in a public GitHub issue or pull request.**
2. Email **shettyshlok87@gmail.com** (or contact the repository maintainer via GitHub Private Vulnerability Reporting) with the subject `[SECURITY] HistoSight Vulnerability Report`.
3. Provide:
   - Affected endpoint or module (`backend/main.py`, `inference.py`, `stain_norm.py`, etc.)
   - Minimal reproduction payload or curl command
   - Assessment of clinical or infrastructure impact
